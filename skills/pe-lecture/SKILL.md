## 核心反例 R1-R8（按高频到低频）

### R1 反例·答案/解析里的"前缀 X"冗余

**错的样子**（4 种变体）：
- `答案：✓。讲义原话：""`
- `答案：✓。讲义原文：""`
- `答案：✓。原文：""`
- `答案：✓。讲义：""`

**对的样子（R1 严格版）**：`答案：✓。""`——**直接**写中文引号，**零前缀**。

**根因**：agent 写答案/解析时，**反射性**给引文加"出处标签"——但学员看稿时，引文紧跟在"答案："后，**本身就在"原文出处"语境里**。

**踩坑曲线**（v2.2→v2.6 实战 50+ 篇累计）：
- 3 体育游戏 v2.2：30+ 处（老板手动全去）
- 4 运动解剖学 v2.3：7 处
- 5 运动生理学 01：8 处
- 1 学校体育学 02/03/04 批量反弹：6 处
- 8 田径 02/03：5 处（自己写仍反弹）
- 2/6/7 别家接手 20 篇：151 处

**R1 命中曲线铁律**：
- 反弹 5 次，**肌肉记忆尚未真正形成**
- 反弹节点：批量写第 2-4 篇时
- **唯一可信信号**：每篇写完立即跑 R1 自查，**不写完所有再一起查**

**修法**（4 道防线）：
1. **写稿时**：脑里钉钉——"答案/解析里引用讲义，**直接**写引号，**不加任何前缀**"
2. **写完自查**：`grep -E "讲义原话：|原文：|教材：|讲义：" *.md` 必须 0
3. **严格 R1 自查脚本**（见 `scripts/r1_self_check.py`）
4. **patch 后再查**——replace_all 不是终态（见 R2）

### R2 反例·patch 工具 replace_all 残留句式

**错的样子**：`答案：**✕**。：""继续坚持运动……""——坚持不是停止。`

patch 把"讲义原话：" → "" 后留下"。"+"："的孤冒号。

**根因**：patch 是字符串级替换，**不感知中文标点配对**。

**修法**：
- patch 时 old_string 显式带"。"：`"**✕**。讲义原话："`
- 或整体替换：`"答案：**✕**。讲义原话：……"` → `"答案：**✕**。……"`
- R2 自查：`grep -E "。：|\\.:" *.md` 必须 0

### R3 反例·"优化记录"自指违规

**错的样子**：讲稿末尾"本讲稿 v1 优化记录"里写"严格守住 R1 反例铁律，不加'讲义原话/原文'前缀"——这句**元描述**里出现"讲义原话"和"原文"，触发 R1 自查脚本误报。

**修法**：
- 优化记录里写 R1 规则时，用"R1 规则""前缀 X"等概括
- 或 R1 自查脚本加白名单：跳过 `> **本讲稿 v? 优化记录**` 区块

### R4 反例（合规澄清）·模块二"考点解析"主标题

**易误判的合规用法**：模块二/三"考点解析"里用 `讲义""`（**冒号紧跟**）格式标注原文引用——这是 v2.3 模板的**标准结构**。

**R1 违规 vs 合规判别铁律**：
- ✅ 合规：`### 1. 标题` + `讲义""`（模块二/三的主标题引出词）
- ❌ 违规：`答案：✓。原文：""`（**答案/解析**区用"原文："作前缀）

**实战最优解**：模块二/三主标题**直接用"讲义"+"引文"**（不带"原文/原话"），保证全篇 R1 = 0。

### R5 反例·列举式前缀（更隐蔽，v2.5 实战 67% 命中率）

**错的样子**：
```
答案：C. 竞争性（"竞争性是…杠杆"——考点：模块二-2 竞技体育基本特点）
```

**修法**：`grep "考点：模块" *.md` 应返回 0；改为"考点定位"段落统一说明（模块五"知识拓展"本来就要写）。

### R6 反例（v2.6 新增）·批量 re.sub 后的"X："" 孤冒号

**错的样子**：
```
答案：**✕**。：""改善气体交换……""——是改善不是堆积。
```

**根因**：批量 re.sub 删了"讲义原话："前缀，但留下了原"。"+"讲义原话：""被替换为"。X："的格式——R2 修补时漏的句号位置。

**修法**：
- re.sub 脚本后**强制 grep `[。.]\s*[:：]\s*[""]`**，**第二轮 patch 修**
- 或在 re.sub 里**带句号模式**：`re.sub(r'。\s*讲义原话：', '。', text)`

### R7 反例（v1.3 新增，r1_self_check.py 字面匹配类）·"原文：" 字面匹配误伤 SKILL v2.3 "回原文" 步骤名

**错的样子**（违反 SKILL v2.3 第 198 行模板 + 触发脚本 R1_原文 字面匹配）：
```
2. 回原文：起源=1891年、斯普林菲尔德、奈·史密斯……
```

**对的样子**（按 SKILL 模板，步骤名内部用 `——` 衔接）：
```
2. 回原文——起源=1891年、斯普林菲尔德、奈·史密斯……
```

**根因（双重）**：
- SKILL v2.3 第 198 行模板规定：`2. 第二步：{回原文/回定义——这一步要写出……}`（用 `——` 而非 `：`）
- agent 实际写成 `第二步：回原文：起源=……`（冒号替代了破折号）—— **模板违规**
- 同时 r1_self_check.py 的 `r1_v3 = text.count("原文：")` 是字面字符串匹配，**会误伤**这个写法

**实战信号**：
- 2026-06-13 审核田径+篮球 8 篇时命中 4 处误报（篮球 01/02 各 2 处）
- 全部集中在模块三"解题思路第二步"

**修法（2 选 1）**：
1. **稿子侧**（最小修改 + 符合 SKILL 模板）：`第二步：回原文：` → `第二步：回原文——`（冒号改破折号）
2. **脚本侧**（治本 + 避免逐稿手动改）：r1_self_check.py 加白名单——跳过 `^2\. 回原文` 行（v1.3 已实施）

**判别铁律**：
- ✅ 合规：`2. 回原文——xxx`（破折号衔接，引出内容）
- ❌ 真违规（R1 原始定义）：`答案：✓。原文：""……""`（答案/解析区作引文前缀）
- ⚠️ 误伤场景（R7 专属）：`2. 回原文：xxx`（冒号 + 步骤内引用，触发字面匹配）

**v1.7 升级（2026-06-15）**：`r1_self_check.py` 已实施 R12 白名单——`r1_real = r["R1_原文:"] - r["R12_误报候选:"]`（从 R1_原文 计数中减去 R12 误报候选），并单独输出"已豁免"提示。**实战验证**：乒乓/羽毛/网球 12 篇全部 0 反弹过 R1=0（无需手动破折号修正）。

### R8 反例（v1.4 新增，clean_md_content 严格匹配类）·AI 实战稿"优化记录"格式非标准导致元数据残留

**错的样子**（docx 校核器"元数据残留"=2 触发）：
```
本讲稿 v1.0 优化记录： - v1.0：根据v2.4模板初版生成，覆盖运球/持球突破/防守/抢篮板球四大主题
```

**对的样子**：clean_md_content 必须增强正则兼容 4 种格式（带不带 `>` + 带不带 `**`），删干净。

**根因（双重）**：
- SKILL v2.3 模板规定"优化记录"段用 `> **本讲稿 v1 优化记录**` 引用块 + 加粗（多行格式）
- clean_md_content 正则 `^>\s*\*\*本讲稿 v\d+(\.\d+)?\s*优化记录\*\*` 严格匹配该格式
- 但 AI 实战稿常写成 `本讲稿 v1.0 优化记录：...`（**无 `>` + 无 `**` + 单行**）—— **严格匹配漏删**

**实战信号**：
- 2026-06-13 下册 docx 合并实战命中 2 处：篮球 03 主要技术（下）+ 篮球 04 裁判方法与场地
- 首次跑 4 道校核：H1=2 ✅ / 元信息=40 ✅ / 暗红=17 ✅ / 表格=27 ✅ / **元数据残留=2 ❌**

**修法（增强 clean 函数正则，兼容 4 种格式）**：
```python
# 旧：单一严格匹配
if re.match(r"^>\s*\*\*本讲稿 v\d+(\.\d+)?\s*优化记录\*\*", stripped):

# 新：兼容 4 种格式
if re.match(r"^(?:>\s*)?(?:\*\*)?本讲稿\s*v\d+(\.\d+)?\s*优化记录", stripped):
```

**判别铁律**：
- ❌ 严格匹配漏删：`本讲稿 v1.0 优化记录：xxx`（无 `>` + 无 `**`）
- ✅ 增强正则兼容：4 种格式全覆盖（SKILL 标准 + 3 种 AI 实战常见变体）

**下次怎么避**：
- merge 脚本 main() 跑前**先用 r1_self_check.py 在 md 上做预检**——把"元数据残留"作为预检项
- 或 clean 函数默认开 4 种格式兼容（umbrella v1.4 已实施）

### R13 反例·patch 工具嵌套错位元教训

**错的样子**：patch Python 脚本时 old_string/new_string 看似精确对齐，实际**因 Python 缩进语义**导致嵌套错位——把"独立 if 块"误嵌套进另一个"if 块"里，结果逻辑静默死代码。

**实战坑**：2026-06-15 patch `merge_md_to_docx_v1.py` 的 clean_md_content 时，**R11 升级 4 句正则**被错误地**嵌套进 `if in_code:` 块内**（只 in_code=True 才执行）——所有正文清理逻辑**全部失效**。

**根因**：patch 工具字符串替换**不感知 Python 缩进语义**。

**4 道自验防线（v1.5+ patch 后必跑）**：① `ast.parse()` 语法 OK ② `importlib.reload()` 模块加载 OK ③ 单元测试（构造 4 种"本讲稿 v? 优化记录"格式验证全被清掉）④ 端到端真数据测试。

**下次怎么避**：patch 任何 Python 逻辑前，**先 read_file 看上下文缩进**，**写 old_string 时显式包含前导空白**。

### R14 反例·execute_code 沙箱 50KB stdout + 5min timeout 双重限制

**错的样子**：`execute_code` 跑 Python 脚本，print 输出 > 50 KB，**触发 BLOCKED**——agent 卡住等 user 响应但 user 看不到。

**对的样子**：长 print 输出**写文件**（`f.write()`）→ `read_file` 分页读；或**改用 `terminal` 工具跑**（无 50KB cap）。

**实战坑**：2026-06-15 patch 田径+篮球 8 篇时，**在 execute_code 里跑 8 篇批量 patch**——print 50 处违规行 + 上下文，stdout > 50 KB，**再次触发 BLOCKED**。

**下次怎么避**：**估算 stdout 大小**——批量 patch 8 篇 × 50 行 × 80 字符 ≈ 32 KB，接近上限。**默认走 terminal + temp.py + tee**——execute_code 只适合 < 30 KB 输出。

### R15 反例（v1.6+ 新增）·python-pptx 切片语法陷阱

**错的样子**：`for i, slide in enumerate(p.slides[:5])` —— **`Slide` 对象不支持 `[:]` 切片**。报错：
```
AttributeError: 'list' object has no attribute 'rId'
```

**对的样子**：`for i, slide in enumerate(list(p.slides)[:5])` —— **先转 list 再切片**。

**实战坑**：2026-06-15 网球 + 2026-06-18 游泳 + 2026-06-18 运动生理 **3 次踩同一坑**。

**下次怎么避**：写 PPT 抽取脚本时**默认 `list(p.slides)` 起步**——多 6 个字符省 30 分钟 debug。

### R16 反例（v1.6+ 新增）·workbuddy venv 是 docx/pptx 唯一可用 Python 环境

**错的样子**：用 `<Python 环境>` 跑 docx 脚本——**`ModuleNotFoundError: No module named 'docx'`**。

**对的样子**：用 **`<Python 环境>`**—— workbuddy venv 装了 docx + pptx + openpyxl。

**根因**：hermes-agent venv 当前 path 不可 import docx（被踢出 sys.path）；workbuddy venv 是替代环境。

**下次怎么避**：
- **PPT/Word/Excel 抽取/合并脚本** → 默认走 workbuddy venv
- **R1 自查脚本** → 走 workbuddy venv
- **exec_code/terminal 默认调用** → 改用 workbuddy venv
- **bash 转义陷阱**——Windows 路径含空格时**用 `r'C:/...'` 正斜杠**避免双反斜杠
- **`subprocess.run([r'C:/...'])` 列表形式**避免空格转义坑

### R17 反例（v1.7+ 新增）·docx 老板原版用数字 style_id 不是字符串

**错的样子**：用 `OxmlElement` 创建 Heading 段落时设 `pStyle.set(qn("w:val"), "Heading2")`（字符串）——**老板 docx 不识别**。

**对的样子**：`pStyle.set(qn("w:val"), "4")`（**数字 ID**）—— 老板原版 Heading 1/2/3/4 = 数字 3/4/5/6。

**实战坑（2026-06-18 运动生理 4 篇插入上册 v3）**：第一次脚本用字符串"Heading2"，插入后 Heading 真样式全部失效（被渲染为 Normal）—— 必须用 `doc.styles[i].style_id` 查到实际数字。

**下次怎么避**：处理老板 docx 时**先 `style_id_map = {s.name: s.style_id for s in doc.styles}`**——拿到映射后再 set。

### R18 反例（v1.7+ 新增）·body.insert() 位置插入顺序陷阱

**错的样子**：`body.insert(target_idx, elem)` 用**倒序遍历**插入——后插入的反而排在前。

**对的样子**：用**正序插入到同一位置**——`target_idx` 不变，每次插完 `target` 自动推后一位；或用 `body.insert(list(body).index(target_p_element), elem)` + **正序遍历**。

**实战坑（2026-06-18 运动生理 v3 第一次）**：用 `reversed(new_elements)` + `body.insert(target_idx, elem)`——结果 4 篇**顺序全反**（04 循环→03 呼吸→02 骨骼肌下→01 骨骼肌上），应该 01→02→03→04。

**下次怎么避**：用 `body.insert(list(body).index(target_p_element), elem)` + **正序 for 循环**（不是 reversed）。

## R1 反弹根因（v2.6 反思）

5 次 R1 反弹，**不是因为 agent 不会写**，**而是因为**：

1. **批量时脑子从"学员稿定位"切到"信息密度最大化"**——为了让答案更有说服力，反射性加"讲义原话："做权威背书
2. **写第 2-4 篇时容易松懈**——第 1 篇是 fresh attention，**后面疲劳**
3. **写完后立刻看下一题**，没跑 R1 自查

**唯一解法**：**每篇写完立即跑 R1 自查**（不要等所有写完一起查）。**R1 反弹是不可消除的，只能降到 0（每次写后查）**。

## 批量审核工作流（v1.3 新增）

## 长稿 write_file 截断陷阱（v2.6 新增）

**错的样子**：用 `write_file` 写一篇 1.5-2 万字的长稿——**写完后发现最后一两个模块（5/6/7）被截断**。

**根因**：write_file 工具在单次调用有**字符数上限**（实测 1.5-2 万字会触发）。长稿分两次写：先主体，再 patch 补"五、知识拓展/六、易错点拨/七、记忆口诀"。

**修法**：
- **预估字数**：用临时脚本算 +1500-2000 字符冗余
- **长稿拆 2 段写**：前 1-1.5 万字用 write_file，后面用 patch 补
- **写完立即自查字数 + R1**—— 不要等所有写完
- **写长稿前先 `$env:TEMP/` 落临时文件**，让 write_file 从临时文件读（**不适用于本任务**——临时文件还得 read_file 二次读）

## execute_code 沙箱超时陷阱（v2.6 新增）

**错的样子**：在 `execute_code` 里跑 Python 脚本，stdout 有 60+ KB 的 print 输出——`BLOCKED: execute_code script timed out without user response` 触发。

**根因**：execute_code 沙箱有 **5 分钟 timeout + 50 KB stdout cap**——长 print 撞 cap 后被强制中断，**但 user 不能响应 → BLOCKED**。

**修法**：
- **长 print 输出写到文件**（`f.write()`）→ read_file 分页读
- **拆小循环**：每次 print 10-20 条 + 计数器
- **不用 execute_code 跑长 print**——改用 search_files 单独抽行
- **本任务**（写稿+自查）execute_code 实际**用得不多**——主要用在 R1 re.sub 批量修复，**输出 < 1 KB，OK**
